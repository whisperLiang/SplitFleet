# CoSplit-UCB

CoSplit-UCB 是 SplitFleet 唯一的默认自适应分割策略。库接口、原生 Flower 策略和真机实验入口共用同一实现；无需选择成本模型或算法版本。

## 初始化与训练

1. 从准入目录选择最接近 0%、25%、75%、100% 的四个结构锚点；目录较小时去重。
2. 每个锚点执行一个预热 batch 和一个计时 batch。临时优化器使用正式训练的优化器工厂，客户端更新其拥有的前缀参数，服务端更新后缀参数。
3. 校准结束或发生异常时，恢复参数、缓冲区、梯度、模块训练模式与随机数状态，丢弃临时优化器。校准计入实验总耗时。
4. 每轮联合选择客户端分割点，从第一轮搜索完整的可行候选目录，并执行内存、ABI、故障冷却和最小驻留约束。
5. 实际 batch 反馈汇总为轮级观测，以实际批次数加权更新计算与批次通信成本；每轮只衰减一次。模型状态交换每客户端每轮更新一次。

评估只绑定设备信息，不执行校准。恢复的兼容学习器沿用已有统计量，不重复初始化。持久状态检查算法身份、特征模式、图签名、后端、向量维度与回归约束，不自动导入不兼容状态。

## 成本模型

| 成本 | 特征与学习方法 |
|---|---|
| 客户端前向、反向 | 13 维上下文；实际优化器拥有的参数比例、结构位置、batch size、设备状态；共享执行组的折扣回归与局部残差 |
| 服务端后缀 | 13 维上下文；实际拥有的后缀参数比例、队列、并发、设备状态；全局共享折扣回归与局部残差 |
| 批次通信 | 14 维上下文；对应 batch size 的实际边界载荷大小、链路状态；每客户端学习完整 RPC 传输耗时 |
| 分割切换 | 9 维上下文；位置距离、缓存、准备状态、状态大小；学习实际准备开销 |
| 每轮状态交换 | 5 维上下文；实际下载字节、前缀拥有参数字节作为上传大小代理，以及缺失标记；非负约束折扣回归 |

未知大小保留缺失标记。上传代理并不假定缓冲区或封装字节为零。通信初始样本来自当前部署的 echo RPC；它们是先验，正式训练持续用实际 RPC 耗时更新。计时使用同一主机的单调时钟时长，不相减跨主机时间戳。

状态交换回归通过非负约束求解，保证增大传输字节不会降低预测均值。状态成本在调度中每轮计入一次；批次成本按 batch 数计入，避免重复计算。

## 联合调度与探索

联合求解器模拟共享服务端队列，以预测轮完成时间选择各客户端的分割点。探索动作的预测均值和置信上界都必须不超过基线预测均值的 `1 + epsilon` 倍，默认 `epsilon = 0.05`。多次探索共用一个轮级预算，不能逐项累加额外额度。这是预测预算，不保证实测时长必然满足同一比例。

保留预测缓存、调度模拟缓存与稳定的候选目录；每轮选择一次分割点，不在每个 batch 内迁移参数。

## 使用

```python
from splitfleet.server.placement.cosplit_ucb import (
    CoSplitUCBConfig, CoSplitUCBPlacementPolicy,
)

policy = CoSplitUCBPlacementPolicy(
    candidate_provider=provider,
    config=CoSplitUCBConfig(),
)
```

原生策略自动传入正式优化器工厂与校准样本。直接调用 `prepare_calibration` 时须提供 `optimizer_fn`。真机命令与各模型的训练设置见 [实验指南](README.md)。
