# 放置实验的诊断与压力对照

训练时间差距应先分解为实测阶段，再检验工作负载是否需要联合调度。不能以某个方法获胜为条件选择并行度或网络轨迹。

2026-10-18 对当前图3的20个 SplitFleet 终点进行了全量诊断。RF-DETR 与 DeepLab 的平均批次排队分别约为224 ms和364 ms，已有明显争用；ResNet与BERT约为7 ms和2 ms。旧评分把排队成本固定加到所有候选中，服务端容量下界在200轮中仅1轮主导评分。所有200轮都没有执行探索。缺少受控的网络变化、短训练和完整任务计时会限制可见的调度收益，但这些观察不能单独确定与其他方法耗时差异的因果来源。未整形不等于物理链路不波动，不能单凭配置断言带宽稳定。

原图3最后一次只更新了SplitFleet，其他方法沿用旧源码和旧日期。新的方法对照必须冻结同一运行时，并共享初始化、分区、样本顺序、训练轮数、优化器、评估和传输路径。

## 统一运行时的物理对照

使用 `physical_multitask prepare` 生成一份服务器及客户端输入包，按 `worker_ids` 指定设备人口。将当前实验源码复制到独立且不再修改的目录，使用与该副本匹配的矩阵驱动；入口会在部署前核验驱动版本，并在运行后核验实际队列模型开关。然后运行：

```bash
python -m experiments.placement_stress \
  --deployment deployment.json \
  --bundle bundles/object_detection.pt \
  --source-root frozen_runtime \
  --output results/new_matched_placement \
  --rounds 10 \
  --controllers CoSplit-UCB Independent-UCB Greedy \
  --capacities 1 2 \
  --network-profiles unshaped stationary dynamic
```

部署文件沿用物理运行器的 `hosts`、`server`、`barrier` 和 `transport`，并增加：

```json
{
  "optimizer": "adam",
  "learning_rate": 0.00001,
  "client_server": {
    "bind": "127.0.0.1:19560",
    "connect": "127.0.0.1:19560"
  }
}
```

代理端口必须与服务器和屏障端口不同。三台设备通过同一个实际TCP代理访问协调器，双向限速分别在全部连接间共享。这是全局共享链路，不是每客户端独享的指定带宽。代理不修改网卡、路由、防火墙或管理SSH连接。

所有方法使用同一执行路径和真实执行容量。控制器只接收当前与过去的运行反馈，不能读取未来网络阶段。每个容量/链路块内的方法次序按种子确定性打乱；不同种子应同时平衡执行次序。

默认路径启用等价的预测与候选成本缓存。新增排队响应模型使用 `--queue-work-response` 显式启用，配套默认/启用两组同源消融；单种子开发试验不作为默认切换依据。实验性目标拥有独立的状态身份。2026-10-18留存的开发快照在SplitFleet分支启用了该模型，报告与原始快照明确记录这一范围。

### 负载预测与联合调整的实测门槛

轮间执行器为空不代表下一轮会串行执行。服务时间预测使用紧邻上一训练轮的执行负载；当前GPU利用率更高时保留该读数，同时保留上一轮的活动后缀数。内存可用性和实际排队仍使用当前快照，执行器有活动或容量改变时不套用旧执行负载。

批次成本反馈优先使用 `*_mean_ms`，缺失时兼容原 `*_ms` 字段。后者可能是中位数，不能直接乘批次数当作完整服务工作量。一次性的模型交换与切换成本仍按每轮统计，不随批次数重复。

学习统计记录 `batch_mean_preferred_v1` 身份，旧中位数口径的缓存不会静默混用；升级时使用新的输出目录重新校准。该缓存身份检查不改变新启动运行的切点决策或训练计算。

`--joint-gain-guard` 为默认关闭的实验选项。它先求共享成本模型下的独立选择，只有联合选择预测的最大完成时间收益超过上一完整匹配训练轮的最大绝对预测误差，才接受联合调整。冷启动、缺少协调器RPC计时、批次数/客户端集合或容量改变时回退独立选择。误差只使用已经完成的上一轮，不读取未来网络或未执行候选的时间。该门槛是实测误差滞回，不是未执行动作的统计置信保证；独立回退仍保留共享学习器，安全探索使用原来的独立预算。

该选项拥有独立的状态身份，恢复其学习统计时不复用瞬时误差。验证应在共同的均值反馈、负载预测和执行器代码上做开关对照，并给Greedy、Independent-UCB相同的训练输入和预算。

### 信息匹配与机制消融

Independent-UCB、Greedy和L2S适配器现在也绑定真实服务器采集器。每轮先保存同一个负载快照，再交给各私有策略；跨客户端只共享测量信息，不共享学习统计。旧冻结结果中规划`server_load`为空的情况仍保留，不能与新结果混合作纯机制消融。

原生入口增加`Shared-Independent-UCB`：共享组件学习器，独立选择各客户端的利用动作。用`Independent-UCB`、`Shared-Independent-UCB`、`CoSplit-UCB`三个组，可分别比较共享学习和共享模型下的联合利用。机制验证可给所有组设置`--placement-exploration-limit 0`，避免每客户端与全局探索预算不同造成混杂；该设置不替代默认策略的完整方法对照。关闭`--joint-gain-guard`才能直接观察联合利用，门槛消融应另列。

时间指标应同时报告固定工作量的完整任务时间，以及达到预先指定质量阈值所需的实测`elapsed_sec`。未达到阈值的终点保留为未达标，不能记为零或删除。固定与动态链路使用同一组事先声明的轨迹，并报告各方法实际字节和等待；一个先导种子用于验证机制，不作为稳定优势或显著性证据。

| 网络条件 | 用途 |
|---|---|
| `unshaped` | 保留原网络条件，仍经过同一代理 |
| `dynamic` | 在约1/3训练处下降带宽、增加RTT，约2/3处恢复 |
| `stationary` | 固定带宽与RTT；按等字节/轮假设匹配动态轨迹的总序列化时间及平均RTT |

`stationary`与`dynamic`的匹配是预先声明的协议控制；方法会改变传输量，所以不能宣称两者的实际网络成本相同。每个终点保留代理实际字节、等待和阶段收据。`--pipeline`使传播时延流水化，避免给每16 KiB数据块重复附加一个串行RTT。

2026-10-18机制验证检查发现，`RecordingSplit.configure_fit`曾缺少逐轮发布入口，导致配置了动态轨迹也会停留在初始化速率。入口已修复，矩阵驱动现在同时检查`network_schedule.applied`覆盖0到最后训练轮，以及代理各训练轮的实际速率、RTT和双向正字节。仅验证配置文件或调度器类的单元测试不足以证明训练路径执行了网络切换。历史冻结快照不回写；修订前的固定链路只能核验全程常量速率，不能拆分逐轮代理流量。

客户端人口与后缀执行容量是不同变量。比较3个GPU客户端和6个CPU/GPU客户端时，需要各自生成输入包，并分别声明固定总样本数还是固定每客户端样本数；不能把设备、数据规模和并发同时改变后只归因于并发。

训练长度也需要单独控制。原协议每轮240个训练样本、共10轮，而默认0.98折扣对应约34轮的观测半衰期。可以预先加入更长训练和更多每轮样本的独立块，检查校准/模型交换能否被摊薄，以及在线预测是否收敛。各块内所有方法保持同样的样本、轮次与优化器；不同工作量块之间报告每样本成本和质量，不把更多训练的总时间直接解释为变慢。

## 解释与报告

联合选择的可行域包含独立选择，只能保证相同预测模型下的优化目标不会更差；它不保证真实训练时间占优，也不直接支配使用另一套私有学习器的Independent-UCB。应将预测的联合完工收益与已执行动作的预测误差并列。当前评分采用实测等待、容量下界和可选局部工作量响应，与英文稿中逐批到达/有限执行槽位的完整递推模型有差异，不能把稿件中的模型性质直接当作本执行器的实测保证。

- 同时报完整任务时间、各轮fit跨度、规划耗时、评估耗时、排队、后缀服务、传输字节和最终任务质量。
- 原图3的五个种子用于配对重复；新增开发种子不能与旧源码终点混合计算方法收益。
- 单种子试验用于验证可执行性与发现性能回退，不能据此给出置信区间、显著性或跨任务优势结论。
- 对所有方法采用相同失败规则，保留失败、中断及日志。重跑使用新目录并说明原因，不按时间或质量筛选尝试。
- 原始图3保持原值，只有完成同源、同协议的整组测量及审计后再更新对应图表。
